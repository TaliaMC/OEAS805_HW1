How could I "unstack" the attached dataset so that the different variables in "parameter" are each their own column? The way this is currently set up makes it difficult to associate parameter measurements with the sample of origin

To unstack (pivot) this Chesapeake Bay Program water quality dataset so that each water quality parameter becomes its own column, you need to group the dataset by the columns that uniquely identify each sample, expand the Parameter column into headers, and populate the cells with MeasureValue.

Key Data Columns Identified
Sample Index (Identifying Columns): Station, SampleDate, SampleTime, SampleDepthM, Layer, SampleType, SampleReplicate (and FieldActivityId).

Pivot Variable: Parameter

Pivot Values: MeasureValue

Note on Duplicate Entries: In this dataset, certain parameters (such as DIN) have multiple method codes (e.g., D01A vs D01B) for the same sample event. If you want a strictly 1-row-per-sample table, you should decide whether to aggregate (e.g., mean/first value) or include Method in your sample index.

Option 1: Python (Pandas)
Method A: Keeping 1 row per sample event (handling duplicates via aggregation)
Python
import pandas as pd

# Load dataset
df = pd.read_csv("CBP_TWQM_MAIN_WQ_2021_2026_surface.csv")

# Define columns that identify a unique sample event
sample_id_cols = [
    "Station",
    "SampleDate",
    "SampleTime",
    "SampleDepthM",
    "Layer",
    "SampleType",
    "SampleReplicate",
]

# Pivot so parameters become separate columns
unstacked_df = df.pivot_table(
    index=sample_id_cols,
    columns="Parameter",
    values="MeasureValue",
    aggfunc="first",  # or 'mean' if numerical values differ across methods
).reset_index()

# Save output
unstacked_df.to_csv("WQ_unstacked_surface.csv", index=False)

The reason that cell is affecting your KNN regression comes down to variable scope and variable overwriting in Jupyter Notebooks.

When you run that pH cell above, two specific things happen that break the KNN cell:

1. Overwriting Shared Variable Names (x, y, or DIN)
In Jupyter Notebooks, all cells share the same global workspace.

If your KNN cell uses general variable names like x or y (e.g., model.score(x, y)), or if the variables DIN or temp were updated or modified in the linear regression cell, running the pH cell changes what those variables store in memory.

When the KNN cell runs next, it uses the newly updated variable values (which are now referencing pH instead of WTEMP).

2. Mismatched Feature Names in Pandas DataFrames
When you passed temp (unstacked_data[['WTEMP']]) into KNN_model.fit(), scikit-learn memorized that the input feature matrix had a column named WTEMP.

If the KNN cell accidentally passes pH or a redefined feature variable to KNN_model.predict(), scikit-learn detects the mismatch and throws:

ValueError: Feature names unseen at fit time: - PH. Feature names seen at fit time, yet now missing: - WTEMP

How to Fix It
To keep your notebook clean and prevent cells from interfering with each other:

Use explicit, unique variable names for each model:

For Linear Regression: X_ph, y_din, regr_model

For KNN Regression: X_temp, y_din, knn_model

Self-contain each cell: Define and clean the specific features right inside the cell where they are used so running cells out of order won't break your code.

The error x and y must be the same size happens because plt.scatter() expects a 1D array for the x-axis and a 1D array for the y-axis.

In your code:

x_test has 11 columns (a 2D matrix with shape (N, 11)).

y_test and y_pred are 1D vectors (shape (N,)).

Matplotlib sees 
11×N values on the x-axis versus only 
N values on the y-axis, causing the dimension mismatch error. You cannot plot an 11-dimensional feature matrix directly against a 1-dimensional target on a standard 2D scatter plot.

How to Fix the Plot
Depending on what you want to visualize, there are two primary ways to fix this:

Option 1: Plot Actual DIN vs. Predicted DIN (Recommended for Multi-Feature Models)
To evaluate how well your Random Forest performed overall, plot the actual target values (y_test) on the x-axis against the predicted target values (y_pred) on the y-axis. Points falling close to the 45-degree diagonal line indicate accurate predictions:

max_val = max(y_test.max(), y_pred.max())

    [min_val, max_val],
    [min_val, max_val],

    linewidth=2,

)

plt.show()
