How do I add an empty text file to a git repository on Windows PowerShell?

Use the New-Item cmdlet to create an empty text file, then stage and commit it with Git.

PowerShell
# 1. Create an empty text file
New-Item -ItemType File -Name "example.txt"

# 2. Stage the file for Git
git add example.txt

# 3. Commit the file to your repository
git commit -m "Add empty example.txt file"
If you prefer a shorter command to create the file, echo $null > example.txt or New-Item example.txt will also create a blank file in PowerShell.

How can I open the file to edit it from within PowerShell?

The easiest way to open and edit a text file directly within PowerShell depends on whether you want a command-line editor or a graphical text editor.

1. Terminal Editors (Stay Inside PowerShell)
If you have Micro or Vim installed, you can edit the file directly in the terminal buffer:

PowerShell
# If Micro is installed (simple, modern terminal editor)
micro example.txt

# If Vim is installed
vim example.txt
(Note: Windows PowerShell does not include a built-in terminal editor like nano or vim by default unless installed via Winget or Chocolatey).

2. Graphical Editors (Launches a Window)
To open the file in a separate application window while keeping PowerShell open:

PowerShell
# Open in Windows Notepad
notepad.exe example.txt

# Open in Visual Studio Code (if installed)
code example.txt
3. Quick Terminal Edits (Without Opening an Editor)
If you just need to append a quick line of text to the file without launching an editor, use Add-Content:

PowerShell
Add-Content -Path example.txt -Value "Hello World"
How do I clear a git repository?

To "clear" a Git repository depends on what you are trying to accomplish.

1. Remove All Files and Start fresh (Keep Git History)
If you want to clear out the files in your directory while keeping your project's commit history intact:

PowerShell
# Remove all tracked files from the working directory and staging area
git rm -rf .

# Commit the deletion
git commit -m "Clear all files from repository"
2. Reset to the Latest Commit (Wipe Uncommitted Changes)
If you made changes or added files that you haven't committed yet and want to revert back to your last clean commit:

PowerShell
# Discard all changes to tracked files
git reset --hard HEAD

# Remove all untracked files and directories (-f = force, -d = directories)
git clean -fd
3. Completely Delete the Git Repository (Remove Git Tracking)
If you want to un-git the folder (keep your files, but delete all Git history and repository tracking):

PowerShell
# Remove the hidden .git directory in PowerShell
Remove-Item -Recurse -Force .git
4. Nuke Everything (Delete History & Files Completely)
If you want to completely erase the local repository folder and start over from scratch:

PowerShell
# Navigate up one folder, then remove the entire repository directory
cd ..
Remove-Item -Recurse -Force repository-folder-name
How can I move files into a folder once they've all already been pushed to a git repository?

To move files into a folder in an existing Git repository while preserving their history and tracking, use git mv.

1. Move files using git mv
In PowerShell, create the destination folder if it doesn't exist, then run git mv:

PowerShell
# 1. Create the destination folder (if it doesn't exist yet)
New-Item -ItemType Directory -Name "my-folder"

# 2. Move tracked files into the new directory
git mv example.txt my-folder/
git mv file2.txt my-folder/
Tip: You can also move multiple files at once using wildcards:

PowerShell
git mv *.txt my-folder/
2. Commit and push the changes
git mv automatically stages the file relocations for you. Complete the move by committing and pushing to your remote repository:

PowerShell
# Commit the moved files
git commit -m "Move files into my-folder"

# Push the updated structure to your remote repository
git push
What if you already moved the files manually using File Explorer or PowerShell?
If you used Move-Item or File Explorer instead of git mv, Git will register the action as deleted files and untracked new files. To fix this:

PowerShell
# Stage all deletions and new paths automatically
git add -A

# Commit (Git will automatically detect these as renamed/moved files)
git commit -m "Move files into my-folder"

# Push to remote
git push
